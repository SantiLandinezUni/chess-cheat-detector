# Data Dictionary — Chess Cheat Detector (Part 1)

Version 1.1 · Last updated 12 Nov 2026 (Part 2 lake tables L6–L11)

This file is the single source of truth for every dataset in the project. Code must match it; when code changes a column, update this file in the same commit.

**Conventions:** all timestamps are UTC. `player_id` is always the 16-character keyed hash defined in §5. "PK" = primary key, "FK" = foreign key, "NN" = not null. Tables marked 🔒 contain raw usernames and are restricted.

## 2. Source datasets

### S1 — Lichess PGN games

One record per game: a block of header tags, a blank line, then the move text. Header tags used:

| Tag | Example | Maps to |
|---|---|---|
| `Event` | `Rated Blitz game` | `games.event`, `games.is_tournament` |
| `Site` | `https://lichess.org/abcd1234` | `games.game_id` (last path segment) |
| `White`, `Black` | `someuser` | hashed into `white_id`, `black_id`; raw name only in L4 🔒 |
| `Result` | `1-0` | `games.result` |
| `UTCDate`, `UTCTime` | `2026.09.14`, `17:59:48` | `games.started_at` |
| `WhiteElo`, `BlackElo` | `1854` | `games.white_elo`, `games.black_elo` |
| `WhiteRatingDiff`, `BlackRatingDiff` | `+6` | `games.white_rating_diff`, `games.black_rating_diff` |
| `WhiteTitle`, `BlackTitle` | `FM`, `BOT` (optional) | `games.white_title`, `games.black_title` |
| `ECO`, `Opening` | `C20`, `King's Pawn Game` | `games.eco`, `games.opening` |
| `TimeControl` | `180+2`, `-` | `games.time_control`, `base_seconds`, `increment_seconds`, `time_class` |
| `Termination` | `Normal`, `Time forfeit`, `Rules infraction` | `games.termination` |

Move text annotations (optional, per move): `{ [%eval 0.17] [%clk 0:03:00] }`. `%eval` is in pawns from White's point of view (`#-3` = mate in 3 for Black). `%clk` is the mover's clock after the move.

**Measured on the local sample** (`lichess_2026-09_sample.pgn`, first 2,500,000 lines of the September 2026 dump): 124,914 games, the last one truncated (quarantined by the parser); 124,516 with `%clk`; 13,003 with `%eval` (~10%). The proposal's ~6% eval coverage refers to the full Lichess database, not this sample.

### S2 — Lichess user profiles (JSON) 🔒

Response of `POST https://lichess.org/api/users` (body: up to 300 comma-separated usernames). One JSON object per returned account, stored as one line per object (NDJSON). Fields used:

| Field | Type | Meaning |
|---|---|---|
| `id` | string | lowercase username |
| `username` | string | display username |
| `tosViolation` | boolean, optional | account marked for a terms-of-service violation (label source) |
| `disabled` | boolean, optional | account closed |
| `createdAt` | integer (ms epoch) | account creation |
| `seenAt` | integer (ms epoch) | last seen |
| `title` | string, optional | GM, IM, BOT, … |

Usernames that the API doesn't return are recorded with `found = false`. The full response object is kept unchanged in `restricted.user_profiles_raw.response`.

### S3 — Player labels (CSV)

`data/processed/player_labels.csv`, UTF-8, comma-separated, header row, one row per player. Columns are identical to `core.player_labels` (§4.3). It contains no usernames.

## 6. Derived fields and business rules

**player_id:** `HMAC-SHA256(key = LICHESS_HASH_KEY, message = lowercase(username))`, hex digest, first 16 characters. The key is stored only in `.env`. This is pseudonymization, not anonymization: under GDPR the data remains personal data.

**time_class:** estimated duration E = base_seconds + 40 × increment_seconds.

| E (seconds) | time_class |
|---|---|
| < 30 | ultrabullet |
| 30–179 | bullet |
| 180–479 | blitz |
| 480–1499 | rapid |
| ≥ 1500 | classical |
| `TimeControl = "-"` | correspondence |

**move_time_s** for ply p (mover c): `clock_after(p − 2) − clock_after(p) + increment_seconds`. For each side's first move, `clock_after(p − 2)` = `base_seconds`. Null when the game has no clocks. Negative values are real data, not parse errors: lag compensation gives small negatives, and the opponent adding time (+15 s per click, often before a side's first move) raises the clock and gives larger ones (down to −5,237 s in the 2026-09 sample; 2,388 moves, 0.03%, below −1 s). Baselines (`core.baselines`) exclude moves with `move_time_s < 0`.

**Per-game features (L8, Part 2):**
- Population: games with `has_bot = false` and `n_plies > 0`. Timing statistics use only moves with `move_time_s ≥ 0`.
- **Low clock:** the clock after the move (`clock_after_s`) is under 10% of `base_seconds`.
- **Centipawn loss** of a move: how much the mover's evaluation dropped versus the previous ply, from the mover's point of view, floored at 0. Evals are capped at ±1000 cp before differencing. Mate evals (`eval_cp` null) are skipped, and so is any move whose previous ply has no centipawn eval (including ply 1). `acpl` = mean centipawn loss of the player's moves in the game.

**Sessions (L9):** a player's games across all time classes, ordered by `started_at`. A game starts a new session when it starts more than 30 min after the previous game's estimated end, `started_at + 2 × time_used_s` (the opponent's clock use is not in the row; both sides use similar time). Within-session consistency is computed per time class, on sessions with 2+ games in it.

**Anomaly scores (L11):**
- Per feature, a robust z-score against the player-level baseline (L10, `level = player`) of the player's band × time class: `z = (x − p50) / ((p75 − p25) / 1.349)`, using `sd` when the IQR is 0, null when both are 0. Cells with fewer than 30 players in the baseline give no z.
- `anomaly_score` = mean over the available features in the combined set of `min(5, max(0, −z))`: very even move timing (overall, under low clock and across a session), few moves under 2 s, and a centipawn loss below the band. Only the suspicious direction counts, and each term is capped at 5.
- `anomaly_pct` = `percent_rank` of `anomaly_score` within band × time class.

**label:**

| Condition (from S2) | label |
|---|---|
| `tosViolation = true` | positive |
| `found = true`, `disabled` not true, `tosViolation` not true | negative |
| `disabled = true` without `tosViolation`, or `found = false` | unknown |

Labels are proxies for ground truth. `tosViolation` marks any terms-of-service violation, not only engine use; it applies to the account, not to individual games; and undetected cheaters sit in the negative class.

## 8. Kafka topics (Part 2)

### K1 — `lichess.moves`

One message per half-move. **Key** = `game_id` (UTF-8), so all moves of a game go to the same partition, in ply order. **Value** = one UTF-8 JSON object with exactly these fields, in this order. 8 partitions, replication factor 1 (single broker). The Kafka record timestamp equals `timestamp`. Only hashed `player_id` values are sent, never usernames.

| Field | JSON type | Nullable | Description / source (replay producer) |
|---|---|---|---|
| `game_id` | string | no | `moves.game_id` |
| `ply` | integer | no | `moves.ply`, ≥ 1 |
| `player_id` | string | no | hashed mover, `moves.player_id` |
| `color` | string | no | `w` or `b`, `moves.color` |
| `time_class` | string | no | `games.time_class` |
| `elo` | integer | no | mover's rating before the game: `games.white_elo` or `games.black_elo` |
| `clock` | number | yes | mover's clock after the move in seconds, `moves.clock_after_s` |
| `move_time` | number | yes | seconds, `moves.move_time_s` (can be negative, see §6) |
| `eval` | integer | yes | centipawns, White's point of view, `moves.eval_cp` |
| `eval_mate` | integer | yes | mate in N, positive = White mates, `moves.eval_mate` |
| `timestamp` | integer | no | send time, UTC epoch milliseconds |

**Replay selection:** the first N games of a month by `started_at` (optionally from a start time), excluding games with `has_bot = true`, games with `n_plies = 0` and, by default, correspondence. Each move is sent `(started_at − window start + cumulative max(move_time_s, 0) of the game up to this ply) / speed` seconds after the replay starts.
