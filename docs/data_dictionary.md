# Data Dictionary — Chess Cheat Detector (Part 1)

Version 0.1 (draft) · Last updated 30 Oct 2026

This file is the single source of truth for every dataset in the project. Code must match it; when code changes a column, update this file in the same commit.

**Conventions:** all timestamps are UTC. `player_id` is always the 16-character keyed hash defined in §5. "PK" = primary key, "FK" = foreign key, "NN" = not null. Tables marked 🔒 contain raw usernames and are restricted.

---

## 1. Overview

| # | Dataset | Format | Origin | Location |
|---|---|---|---|---|
| S1 | Lichess rated standard games | PGN (zstd) | Lichess monthly dump, CC0 licence | `data/raw/*.pgn` |
| S2 | Lichess user profiles 🔒 | JSON (NDJSON) | Lichess API `POST /api/users` | `data/raw/profiles/*.ndjson`, `restricted.user_profiles_raw` |
| S3 | Player labels | CSV | Generated by `build_labels.py` from S2 | `data/processed/player_labels.csv` → `core.player_labels` |
| S4 | Reference and derived tables | SQL-generated | `sql/generate_reference.sql`, `sql/generate_derived.sql` | `ref.*`, `core.players`, `core.baselines` |
| L1–L4 | Parquet lake | Parquet | Written by `parse_games.py` | `data/lake/{games,moves,quarantine,restricted/identity}` |

**PostgreSQL schemas:** `core` (analytical, pseudonymized), `ref` (reference, SQL-generated), `restricted` 🔒 (usernames, raw API responses; access limited to the label pipeline).

## 2. Source datasets

### S1 — Lichess PGN games

One record per game: a block of header tags, a blank line, then the move text. Header tags used:

| Tag | Example | Maps to |
|---|---|---|
| `Event` | `Rated Blitz game` | `games.event`, `games.is_tournament` |
| `Site` | `https://lichess.org/abcd1234` | `games.game_id` (last path segment) |
| `White`, `Black` | `someuser` | hashed into `white_id`, `black_id`; raw name only in L4 🔒 |
| `Result` | `1-0` | `games.result` |
| `UTCDate`, `UTCTime` | `2026.09.14`, `17:59:48` | `games.started_at` |
| `WhiteElo`, `BlackElo` | `1854` | `games.white_elo`, `games.black_elo` |
| `WhiteRatingDiff`, `BlackRatingDiff` | `+6` | `games.white_rating_diff`, `games.black_rating_diff` |
| `WhiteTitle`, `BlackTitle` | `FM`, `BOT` (optional) | `games.white_title`, `games.black_title` |
| `ECO`, `Opening` | `C20`, `King's Pawn Game` | `games.eco`, `games.opening` |
| `TimeControl` | `180+2`, `-` | `games.time_control`, `base_seconds`, `increment_seconds`, `time_class` |
| `Termination` | `Normal`, `Time forfeit`, `Rules infraction` | `games.termination` |

Move text annotations (optional, per move): `{ [%eval 0.17] [%clk 0:03:00] }`. `%eval` is in pawns from White's point of view (`#-3` = mate in 3 for Black). It is present in about 6% of games. `%clk` is the mover's clock after the move.

### S2 — Lichess user profiles (JSON) 🔒

Response of `POST https://lichess.org/api/users` (body: up to 300 comma-separated usernames). One JSON object per returned account, stored as one line per object (NDJSON). Fields used:

| Field | Type | Meaning |
|---|---|---|
| `id` | string | lowercase username |
| `username` | string | display username |
| `tosViolation` | boolean, optional | account marked for a terms-of-service violation (label source) |
| `disabled` | boolean, optional | account closed |
| `createdAt` | integer (ms epoch) | account creation |
| `seenAt` | integer (ms epoch) | last seen |
| `title` | string, optional | GM, IM, BOT, … |

Usernames that the API doesn't return are recorded with `found = false`. The full response object is kept unchanged in `restricted.user_profiles_raw.response`.

### S3 — Player labels (CSV)

`data/processed/player_labels.csv`, UTF-8, comma-separated, header row, one row per player. Columns are identical to `core.player_labels` (§4.3). It contains no usernames.

## 3. Parquet lake

### L1 — `games`

Partitioned by `source_month`, `time_class`. Grain: one row per game. Same columns as `core.games` (§4.1).

### L2 — `moves`

Partitioned by `source_month`, `time_class`. Grain: one row per half-move (ply). Same columns as `core.moves` (§4.2), plus the partition columns.

### L3 — `quarantine`

Partitioned by `source_month`. Grain: one row per rejected game.

| Column | Type | NN | Description |
|---|---|---|---|
| `source_month` | string `YYYY-MM` | ✓ | dump month |
| `game_id` | string | | if it could be extracted |
| `error_stage` | string | ✓ | `parse` or `dq` |
| `error_code` | string | ✓ | e.g. `unparseable_pgn`, `truncated_record`, `missing_site`, `invalid_result` |
| `error_detail` | string | | exception message or failed-check description |
| `raw_excerpt` | string | | first 500 characters of the record, with the `White` and `Black` header lines removed |
| `quarantined_at` | timestamp | ✓ | |

### L4 — `restricted/identity` 🔒

| Column | Type | NN | Description |
|---|---|---|---|
| `player_id` | string(16) | ✓ PK | keyed hash of the username |
| `username` | string | ✓ | Lichess username as it appears in PGN |
| `first_seen_month` | string `YYYY-MM` | ✓ | first dump month in which the player appears |

## 6. Derived fields and business rules

**player_id:** `HMAC-SHA256(key = LICHESS_HASH_KEY, message = lowercase(username))`, hex digest, first 16 characters. The key is stored only in `.env`. This is pseudonymization, not anonymization: under GDPR the data remains personal data.

**time_class:** estimated duration E = base_seconds + 40 × increment_seconds.

| E (seconds) | time_class |
|---|---|
| < 30 | ultrabullet |
| 30–179 | bullet |
| 180–479 | blitz |
| 480–1499 | rapid |
| ≥ 1500 | classical |
| `TimeControl = "-"` | correspondence |

**move_time_s** for ply p (mover c): `clock_after(p − 2) − clock_after(p) + increment_seconds`. For each side's first move, `clock_after(p − 2)` = `base_seconds`. Null when the game has no clocks.

**label:**

| Condition (from S2) | label |
|---|---|
| `tosViolation = true` | positive |
| `found = true`, `disabled` not true, `tosViolation` not true | negative |
| `disabled = true` without `tosViolation`, or `found = false` | unknown |

Labels are proxies for ground truth. `tosViolation` marks any terms-of-service violation, not only engine use; it applies to the account, not to individual games; and undetected cheaters sit in the negative class.

## 7. Data quality checks

| Check | Level | Applies to |
|---|---|---|
| `game_id` unique and not null | hard | games |
| (`game_id`, `ply`) unique | hard | moves |
| `result` in allowed set | hard | games |
| `white_id` ≠ `black_id` | hard | games |
| every `moves.game_id` exists in `games` | hard | moves |
| `n_plies` = count of moves rows | hard | games, moves |
| Elo between 400 and 3500 | soft | games |
| `move_time_s` < −1 s | soft | moves |
| `n_plies` = 0 | soft | games |
| share of games with `has_clock = false` > 5% | soft | games |
| every player in `games` has a row in `player_labels` | soft | labels |
